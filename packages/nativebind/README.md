# nativebind

Bind C++ modules to Flutter over FFI, QML-style. Write a feature once as a
single C++ file; get typed, reactive Dart view models without writing any FFI
code or bindings by hand.

This package holds both runtimes: the Dart side (`lib/`) and the C++20 side
([`native/`](https://github.com/trevortomlin/nativebind/tree/main/packages/nativebind/native)).
The Dart code is generated by
[`nativebind_generator`](https://github.com/trevortomlin/nativebind/tree/main/packages/nativebind_generator).
**Start with the [quick start](https://github.com/trevortomlin/nativebind#quick-start);
the [guide](https://github.com/trevortomlin/nativebind/blob/main/docs/guide.md) has the details.**

```cpp
// native/modules/player.cpp
#include <nativebind/nativebind.hpp>

class Player : public nativebind::Module {
    NATIVEBIND_MODULE(Player)
public:
    NATIVEBIND_PROP(double, volume, 0.5, .min = 0, .max = 1, .step = 0.05)
    NATIVEBIND_READ(double, position, 0.0)
    NATIVEBIND_LIST(Track, queue)
    NATIVEBIND_SIGNAL(trackChanged, std::string)
    NATIVEBIND_INVOKE void seek(double seconds);
};
```

```dart
final player = Player.instance;
player.volume.value = 0.8;                       // two-way: C++ validates, Flutter reconciles
ValueListenableBuilder(
  valueListenable: player.position,              // rebuilds when C++ assigns it
  builder: (context, s, _) => Text('$s s'),
);
ListView(children: [for (final t in player.queue) Text(t.title)]);   // incremental list
player.trackChanged.listen(print);                // signals are Streams
await player.seek(42);                            // methods return Futures
```

## Setup

1. Add the packages:

   ```sh
   flutter pub add nativebind dev:nativebind_generator
   ```

2. Build your modules into a shared library with CMake. `nativebind_add_modules`
   generates the C++ glue at build time and links the runtime:

   ```cmake
   add_subdirectory(${NATIVEBIND_DIR}/native nativebind)
   add_library(my_backend SHARED)
   nativebind_add_modules(my_backend SOURCES native/modules/player.cpp)
   ```

   [`examples/showcase/native/CMakeLists.txt`](https://github.com/trevortomlin/nativebind/blob/main/examples/showcase/native/CMakeLists.txt)
   is a complete template that finds `NATIVEBIND_DIR` through the app's
   `package_config.json`.

3. Generate the Dart side (rerun after changes, or keep `--watch` running):

   ```sh
   dart run nativebind_generator          # native/ -> lib/nativebind/
   ```

4. Start the runtime before `runApp`:

   ```dart
   import 'package:nativebind/nativebind.dart';
   import 'nativebind/nativebind_modules.dart';

   Future<void> main() async {
     WidgetsFlutterBinding.ensureInitialized();
     await NativeBind.start(library: 'libmy_backend.so', modules: nativebindModules);
     runApp(const App());
   }
   ```

   `start` checks that the generated code matches the native library, then
   loads the complete state, so the first frame shows real values.

## API at a glance

| Dart | From C++ | |
|---|---|---|
| `BoundProperty<T>` | `NATIVEBIND_PROP` | `value`, `write()`, `beginEdit()` for drags, `canWrite`, `isPending` |
| `BoundValue<T>` | `NATIVEBIND_READ` | `value`, `meta`, `doc`, `choices`, `hasValue` |
| `BoundList<T>` | `NATIVEBIND_LIST` | a read-only `List<T>` plus a `changes` stream |
| `BoundSignal<T>` | `NATIVEBIND_SIGNAL` | a broadcast `Stream<T>` |
| `Future<R> method(...)` | `NATIVEBIND_INVOKE` | completes with the C++ result or a `BindInvokeException` |
| `Module.instance` / `Module.instances` | `NATIVEBIND_MODULE` | singleton, or instances spawned by C++ |
| `NativeBind` | | `start`, `stop`, `writeGuard`, `drainNow`, `settle` |
| `FakeNative` | | scripted native side for tests (`package:nativebind/testing.dart`) |

Platforms: Linux (desktop and embedded, e.g. flutter-pi) is built and tested.
